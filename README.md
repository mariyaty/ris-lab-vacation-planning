## Лабораторная работа № 3. Клиентское приложение

В рамках лабораторной работы разработан каркас клиентского приложения для системы планирования графика отпусков и расчёта явочной численности.

Клиентская часть создаётся с использованием Vue 3 и JavaScript. Для запуска приложения используется Vite.

### Реализуемые экраны

1. **Список заявок** — отображение заявок в таблице с номером, темой, идентификатором участка предприятия и статусом.
2. **Создание заявки** — форма с полями `title`, `siteId` и `description`.
3. **Вход в систему** — форма с полями логина и пароля.

Переключение между экранами осуществляется с помощью Vue 3 без перезагрузки страницы. Для отображения заявок используется директива `v-for`.

На данном этапе используются тестовые данные. Подключение серверной части ASP.NET Core и базы данных PostgreSQL не требуется.

### Структура клиентского приложения

```text
frontend/
├── package.json
├── package-lock.json
├── index.html
├── vite.config.js
├── public/
└── src/
    ├── main.js
    ├── App.vue
    └── assets/
```

### Запуск приложения

Для запуска необходим установленный Node.js версии LTS.

Выполните команды из корневой папки репозитория:

```bash
cd frontend
npm install
npm run dev
```

Откройте адрес в браузере:

`http://localhost:5173`

Для остановки сервера разработки нажмите `Ctrl + C` в терминале.

## Лабораторная работа № 4. Компоненты и маршруты Vue

В рамках ЛР4 существующий интерфейс ЛР3 разделён на переиспользуемые компоненты и страницы. Внешний вид и предметная область проекта сохранены.

### Маршруты

| URL | Страница |
|---|---|
| `/` | Список заявок |
| `/new` | Создание заявки |
| `/login` | Вход в систему |

### Структура

```text
frontend/src/
├── main.js
├── App.vue
├── router.js
├── ticketsStore.js
├── assets/main.css
├── components/
│   ├── AppHeader.vue
│   └── TicketTable.vue
└── pages/
    ├── TicketList.vue
    ├── TicketNew.vue
    └── Login.vue
```

`AppHeader.vue` размещён в `App.vue` вне `RouterView`, поэтому боковая навигация остаётся на месте при переходе между страницами. `TicketTable.vue` получает массив заявок через обязательный prop `items`. Общий реактивный массив и функцию создания заявки предоставляет `ticketsStore.js`; отдельное хранилище Pinia не используется. Данные остаются демонстрационными и существуют только пока открыто приложение.

Проверьте страницы `/`, `/new` и `/login`. Также проверьте открытие `/new` прямым переходом по URL, создание заявки и её появление в общем списке.

## Лабораторная работа № 5. Форма и список в памяти

В ЛР5 форма создания заявки связана с единым реактивным массивом в `frontend/src/ticketsStore.js`. В хранилище определены `items`, `nextId` и `addItem`. Поля формы связаны через `v-model`, для `siteId` используется `v-model.number`, а отправка формы выполняется с `@submit.prevent`.

### Правила проверки

- `title`: от 5 до 80 символов после удаления пробелов по краям;
- `siteId`: целое число больше нуля;
- `description`: от 10 до 500 символов после удаления пробелов по краям.

Новая заявка получает статус `New` и временный номер вида `TMP-3`. После успешной отправки форма очищается, приложение возвращается к списку заявок.

**Ограничение:** сервер и база данных пока не подключены. Новые заявки хранятся только в памяти браузера и исчезают после F5; две исходные демонстрационные заявки загружаются снова.

### Запуск

```bash
cd frontend
npm install
npm run dev
```

## Лабораторная работа № 7. Каркас ASP.NET Core Web API

В ЛР7 в корень репозитория добавлен отдельный проект `backend` на ASP.NET Core. Клиентская часть `frontend` сохранена без изменений. Backend предназначен для последующего подключения Vue-клиента; в рамках ЛР7 реализованы только служебные маршруты и инфраструктурный каркас.

### Состав backend

- `GET http://localhost:5000/health` — короткая проверка доступности процесса (`liveness`), возвращает HTTP 200 и `ok`;
- `GET http://localhost:5000/info` — возвращает имя приложения, среду выполнения и учебную версию;
- `http://localhost:5000/swagger` — интерактивная документация API в среде Development;
- `Controllers/` — заготовка контроллера ресурса заявок для следующей лабораторной;
- `Services/` — интерфейс и реализация служебного сервиса, зарегистрированные через Dependency Injection;
- `Models/` — модель ответа служебного маршрута;
- `Data/` — место для будущего слоя доступа к данным.

### Запуск backend

Требуется установленный .NET SDK 8.0 или новее. Команды выполняются из корня репозитория:

```bash
cd backend
dotnet restore
dotnet run
```

При запуске профиль HTTP Development поднимает приложение по адресу `http://localhost:5000`. Затем откройте:

- Swagger: `http://localhost:5000/swagger`;
- проверка доступности: `http://localhost:5000/health`;
- информация о приложении: `http://localhost:5000/info`.

Для остановки сервера нажмите `Ctrl + C`.

### Ограничения ЛР7

`/health` проверяет только то, что процесс запущен и отвечает (`liveness`). Успешный ответ `/health` не подтверждает создание, чтение или сохранение заявок и не заменяет проверку API через Swagger.

В текущей лабораторной работе маршруты создания и чтения заявок не реализуются. Полноценная работа с заявками относится к ЛР8. Данные демонстрационного frontend mock находятся в памяти браузера и сбрасываются после перезагрузки страницы. Постоянное хранение на backend и в PostgreSQL пока не реализовано.

Сервис регистрируется в контейнере DI в `Program.cs` и передаётся обработчику через внедрение зависимостей. Контроллеры не создают сервисы вручную через `new`.
