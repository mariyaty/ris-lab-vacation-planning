# Отчёт по лабораторной работе №2

**Тема:** Архитектура и модель данных информационной системы.

## Цель работы

Определить архитектуру разрабатываемой web-информационной системы, выделить основные сущности и связи между ними, проверить модель на соответствие принципу третьей нормальной формы, описать контракт API и связать требования лабораторной работы №1 с моделью и запросами.

## Используемые средства

- Vue 3 и Vite — клиентское приложение;
- ASP.NET Core — серверное приложение;
- PostgreSQL — база данных;
- Markdown и Mermaid — оформление документации и схем.

## Ход работы

1. Определена трёхзвенная клиент-серверная архитектура: браузерный клиент, сервер API и база данных.
2. Выделены сущности `VacationRequest`, `Site` и `User`.
3. Для сущностей определены первичные и внешние ключи, атрибуты и связи.
4. Подготовлена ER-диаграмма и рассмотрено разделение данных для соблюдения 3НФ.
5. Зафиксированы коды статусов `New`, `InProgress`, `Closed`, `Cancelled` и основные переходы между ними.
6. Составлен контракт API для получения списка и одной заявки, создания заявки, назначения ответственного и изменения статуса.
7. Составлена матрица трассируемости трёх критериев приёмки ЛР1.

## Результаты

В каталоге `docs` подготовлены документы:

| Файл | Содержание |

## Вывод

В ходе лабораторной работы спроектирована архитектура web-ИС и описана модель данных для заявок на планирование отпусков. Определены три основные сущности, их ключи и связи. Название участка хранится в справочнике и связывается с заявкой через внешний ключ `siteId`. Описаны отдельные API-операции для создания заявки, назначения ответственного и изменения статуса. Матрица требований показывает, каким образом проектные решения обеспечивают критерии приёмки ЛР1.
