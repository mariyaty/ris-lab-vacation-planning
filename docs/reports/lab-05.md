# Отчёт по лабораторной работе № 5

**Дисциплина:** Технология разработки информационных систем  
**Тема:** Vue 3: форма и список в памяти  
**Выполнила:** Крец Мария Романовна  
**Группа:** ТРИС-1-23  
**Проект:** ИИ-система планирования графика отпусков и расчёта явочной численности для транспортного предприятия (заказ РЖД)

## Цель работы

Связать форму создания заявки с общим реактивным массивом, реализовать клиентскую валидацию и проверить успешную отправку, отказ для некорректных данных и поведение данных после перезагрузки страницы.

## Используемые средства

- Vue 3;
- JavaScript;
- Vite;
- Vue Router;
- Git и GitHub Codespaces.

## Ход работы

1. В `frontend/src/ticketsStore.js` выделен единый реактивный массив `items`, счётчик `nextId` и функция `addItem`.
2. Компоненты списка и боковой навигации используют один общий источник данных.
3. В `TicketNew.vue` поля темы, номера участка и описания связаны с состоянием формы через `v-model`.
4. Для номера участка используется `v-model.number`, чтобы передавать числовое значение.
5. Отправка реализована через `<form @submit.prevent="onCreate">`, поэтому Enter не перезагружает страницу.
6. Добавлена клиентская проверка: тема — от 5 до 80 символов после `trim()`, номер участка — целое число больше нуля, описание — от 10 до 500 символов после `trim()`.
7. Ошибки отображаются рядом с соответствующими полями. При ошибках запись в массив не добавляется.
8. При успешной отправке создаётся объект с полями `id`, `number`, `title`, `siteId`, `description`, `status`; статус всегда `New`, учебный номер формируется как `TMP-{id}`.
9. После успешного добавления форма очищается, а приложение переходит на страницу списка заявок.
10. Существующий дизайн, маршруты и демонстрационные заявки ЛР4 сохранены.

## Проверка работы

После запуска приложения из каталога `frontend` командой `npm run dev` проверьте следующие сценарии в браузере:

| Сценарий | Действия | Ожидаемый результат |
|---|---|---|
| Успешное создание | Тема не короче 5 символов, участок `2`, описание не короче 10 символов; нажать «Создать заявку» | Переход на `/`, новая запись появляется первой в таблице со статусом «Новая» и номером вида `TMP-3` |
| Отказ по теме | На `/new` ввести тему `abc` и заполнить остальные поля корректно | Под полем темы появляется ошибка; запись не добавляется |
| Отказ по участку | Указать `0`, отрицательное или дробное значение | Под полем участка появляется ошибка; запись не добавляется |
| Отказ по описанию | Ввести описание короче 10 символов | Под полем описания появляется ошибка; запись не добавляется |
| Отправка клавишей Enter | Заполнить корректную форму и нажать Enter | Форма отправляется обработчиком Vue без перезагрузки страницы |
| Тип `siteId` | Ввести `2` в числовое поле | В объекте заявки `siteId` хранится как число |
| Перезагрузка | Создать заявку, затем нажать F5 | Добавленная заявка исчезает, исходные демонстрационные записи остаются; ожидаемо: сервера и БД пока нет |

**Важно:** данные хранятся только в памяти браузера. Исчезновение созданной в текущем запуске заявки после F5 является ожидаемым результатом этой лабораторной работы.

## Вывод

В ходе лабораторной работы форма создания заявки связана с единым реактивным массивом Vue 3. Реализованы проверки полей, вывод сообщений об ошибках, числовое связывание `siteId` и предотвращение стандартной перезагрузки HTML-формы. При корректных данных новая заявка добавляется в общий список и получает статус `New`. Сервер и база данных не подключались, поэтому состояние списка после перезагрузки страницы сбрасывается.
