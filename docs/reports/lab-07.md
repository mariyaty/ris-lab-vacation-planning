# Отчёт по лабораторной работе № 7

**Дисциплина:** Технология разработки информационных систем и веб-приложений  
**Тема:** ASP.NET Core: каркас Web API  
**Выполнила:** Крец Мария Романовна  
**Группа:** ТРИС-1-23  
**Проект:** ИИ-система планирования графика отпусков и расчёта явочной численности для транспортного предприятия (заказ РЖД)

## Цель работы

Создать в существующем репозитории серверный проект ASP.NET Core на HTTP-порту 5000, подключить Swagger, реализовать служебные маршруты `/health` и `/info`, подготовить структуру слоёв приложения и зарегистрировать сервис через Dependency Injection.

## Используемые средства

- C#;
- .NET SDK 8.0 или новее;
- ASP.NET Core Web API;
- Swagger / Swashbuckle;
- Visual Studio Code или другая IDE;
- Git.

## Исходное состояние проекта

В качестве основы использован репозиторий после ЛР6. Клиентское приложение Vue 3, его API-модуль, mock-реализация, маршруты, компоненты и стили сохранены. Серверная часть добавлена в отдельную папку `backend` на одном уровне с `frontend`.

## Ход работы

1. Проверена структура репозитория после ЛР6 и наличие клиентского приложения в папке `frontend`.
2. Проверена доступность .NET SDK командой `dotnet --version`. Для выполнения проекта требуется SDK версии 8.0 или новее.
3. В корне репозитория создан отдельный проект ASP.NET Core Web API в каталоге `backend`.
4. В `backend.csproj` задана целевая платформа `net8.0` и подключён пакет `Swashbuckle.AspNetCore` для формирования Swagger UI.
5. В `Program.cs` зарегистрированы контроллеры, генератор описания API и Swagger. Swagger включается в среде Development.
6. В `Properties/launchSettings.json` настроен профиль Development с HTTP-адресом `http://localhost:5000`.
7. Добавлен маршрут `GET /health`. Он возвращает HTTP 200 и короткий ответ `ok`. Маршрут не принимает и не обрабатывает поля заявки.
8. Добавлен маршрут `GET /info`. Он возвращает название приложения, имя среды выполнения и учебную версию.
9. Созданы папки `Controllers`, `Services`, `Models` и `Data`. В `Controllers` размещена заготовка `TicketsController` без действий создания и чтения заявок. В `Models` добавлена модель ответа `/info`; папка `Data` подготовлена для будущего слоя доступа к данным.
10. Созданы интерфейс `IApplicationInfoService` и реализация `ApplicationInfoService`. Сервис зарегистрирован в `Program.cs` через DI и внедряется в обработчик `/info`.
11. В `.gitignore` добавлены исключения `**/bin/` и `**/obj/`, чтобы результаты сборки .NET не попадали в Git.
12. Обновлён `README.md`: добавлены команды запуска backend, адреса Swagger и служебных маршрутов, а также ограничения текущей лабораторной работы.

## Запуск backend

Команды выполняются из корня репозитория:

```bash
cd backend
dotnet restore
dotnet run
```

При успешном запуске приложение должно сообщить, что слушает адрес `http://localhost:5000`.

## Проверка маршрутов

| Адрес | Ожидаемый результат |
|---|---|
| `http://localhost:5000/swagger` | Открывается Swagger UI в среде Development |
| `http://localhost:5000/health` | HTTP 200, ответ `ok` |
| `http://localhost:5000/info` | JSON с названием приложения, средой и версией ЛР7 |

### Чеклист `/health` ≠ создание

| Утверждение | Результат |
|---|---|
| `/health` возвращает `200` без тела заявки | Да, предусмотрено реализацией маршрута |
| `/health` не принимает `title`, `siteId`, `description` | Да |
| Успешный `/health` не доказывает работу POST | Да |
| Создание главного объекта относится к ЛР8 | Да |
| README объясняет различие между liveness и созданием заявки | Да |
| Swagger и `/health` проверяются отдельно | Требуется подтвердить локальным запуском |

### Место для доказательств выполнения

После локального запуска добавить в этот раздел скриншоты:

1. Swagger UI по адресу `http://localhost:5000/swagger`.
2. Ответ `http://localhost:5000/health` со статусом 200 и текстом `ok`.
3. Ответ `http://localhost:5000/info` с JSON-данными.
4. Терминал с сообщением `Now listening on: http://localhost:5000`.

## Ограничения лабораторной работы

Маршрут `/health` выполняет только проверку доступности процесса (liveness). Он не проверяет создание заявки, валидацию полей, сохранение данных или работу базы данных. В ЛР7 не реализуются `GET /api/tickets`, `POST /api/tickets` и полный CRUD. Эти операции относятся к следующей лабораторной работе.

Демонстрационные заявки frontend mock хранятся в памяти браузера и сбрасываются после перезагрузки страницы. Постоянное хранение заявок на backend и в PostgreSQL на данном этапе не реализовано.

Сервис подключён через DI: реализация регистрируется в `Program.cs`, а зависимость передаётся обработчику. Контроллер не создаёт сервис через `new`. Это позволяет в дальнейшем заменить реализацию сервиса, не переписывая контроллер.

## Вывод

В ходе лабораторной работы в существующий проект добавлен отдельный серверный каркас ASP.NET Core Web API. Настроен HTTP-порт 5000, подключён Swagger, созданы служебные маршруты `/health` и `/info`, подготовлены основные папки серверной архитектуры и зарегистрирован сервис через Dependency Injection. Клиентская часть Vue 3 из предыдущих лабораторных сохранена. Создание и чтение заявок, а также подключение PostgreSQL намеренно не реализованы и запланированы на следующие этапы разработки.
