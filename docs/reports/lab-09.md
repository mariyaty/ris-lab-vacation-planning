## Цель работы

Создать схему PostgreSQL для предметной области проекта, определить таблицы и связи между ними, добавить учебные данные и выполнить SQL-запросы с фильтрацией, сортировкой, `JOIN` и `GROUP BY`.

- SQL;
- Git и GitHub.

## Проектирование схемы

Для хранения данных определены три таблицы:

- `sites` — справочник участков предприятия;
- `users` — пользователи системы;
- `vacation_requests` — заявки на планирование отпусков.

Таблица `vacation_requests` содержит внешние ключи `site_id`, `created_by_user_id` и `assignee_user_id`. Поле `assignee_user_id` допускает `NULL`, поскольку новая заявка может быть создана без назначенного ответственного.

Для поля `status` установлено ограничение `CHECK`, допускающее только четыре значения: `New`, `InProgress`, `Closed`, `Cancelled`. Для идентификаторов настроены первичные ключи. Для номера заявки и логина пользователя обеспечена уникальность.

## Индексы

В схеме созданы индексы:

- `vacation_requests_status_idx` — ускоряет фильтрацию заявок по статусу;
- `vacation_requests_site_id_idx` — ускоряет поиск и соединение заявок с участками;
- `vacation_requests_created_at_idx` — помогает при сортировке по дате создания;
- `vacation_requests_assignee_user_id_idx` — ускоряет поиск заявок по ответственному.

## Учебные данные

В `seed.sql` предусмотрены:

- два участка предприятия;
- три пользователя с ролями `HRSpecialist`, `Planner`, `Manager`;
- четыре заявки — по одной для каждого допустимого статуса.

Данные являются вымышленными и предназначены только для учебной проверки.

## Выполненные SQL-запросы

В `db/queries.sql` подготовлены запросы:

1. Выборка новых заявок с сортировкой по дате создания (`WHERE`, `ORDER BY`).
2. Соединение заявок со справочником участков (`JOIN`) для отображения названия участка.
3. Подсчёт количества заявок по статусам (`GROUP BY`, `COUNT`).
4. Дополнительное соединение с таблицей пользователей для отображения автора и ответственного.
5. Проверка ограничения `CHECK` попыткой вставки недопустимого статуса `Done`.
