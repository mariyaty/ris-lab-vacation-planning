# Матрица трассируемости требований

## 1. Назначение

Матрица связывает критерии приёмки лабораторной работы №1 с полями модели данных и запросами API. Это позволяет проверить, что каждое требование поддерживается проектируемой архитектурой.

## 2. Матрица требований

| № | Требование / критерий ЛР1 | Сущность и поля | API | Проверка результата |
|---|---|---|---|---|
| 1 | Кадровый специалист создаёт заявку с `title` длиной 5–80 символов, существующим `siteId` и `description` длиной 10–500 символов. Сервер присваивает номер и статус `New` | `VacationRequest`: `id`, `number`, `title`, `description`, `status`, `siteId`, `createdByUserId`, `createdAt`; `Site.id`; `User.id` | `POST /api/vacation-requests` | Ответ `201 Created`; возвращены `id` и `number`; статус равен `New`; `assigneeUserId` равен `null`. Некорректные данные отклоняются |
| 2 | Кадровый специалист отдельно назначает ответственного; статус остаётся `New` | `VacationRequest.assigneeUserId`, `VacationRequest.status`; `User.id`, `User.role` | `PATCH /api/vacation-requests/{id}/assignee` | Ответ `200 OK`; `assigneeUserId` соответствует выбранному Planner; статус не изменился |
| 3 | Только назначенный исполнитель может перевести свою заявку из `New` в `InProgress` | `VacationRequest.assigneeUserId`, `VacationRequest.status`; `User.id`, `User.role` | `PATCH /api/vacation-requests/{id}/status` | Назначенный Planner получает успешный ответ, статус становится `InProgress`; попытка другого пользователя отклоняется |

## 3. Связь требований с архитектурными компонентами

| Компонент | Участие в выполнении требований |
|---|---|
| Vue 3 | Предоставляет форму создания, список заявок и элементы назначения/смены статуса |
| ASP.NET Core | Проверяет поля, существование участка и пользователя, роль и право на действие; формирует номер и начальный статус |
| PostgreSQL | Хранит заявки, участки, пользователей и связи между ними |

## 4. Вывод

Все три критерия приёмки ЛР1 отражены в модели данных и контракте API. Создание, назначение ответственного и изменение статуса разделены на самостоятельные операции. Проверка прав выполняется сервером, а отменённые заявки сохраняются в базе данных.
